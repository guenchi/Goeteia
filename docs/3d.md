# 3D for the AI era

*Video in, game asset out.*

A martial-arts clip instead of a motion-capture stage. A character
turnaround instead of a month of sculpting and rigging. AI is
already good at producing reference imagery — designs, turntables,
motion video. It is still bad at producing what a game engine
actually eats: a rigged, skinned, textured, animated character.
That gap is the industry's chokepoint, and closing it does not
need a bigger model. It needs a pipeline where every step is
checkable by a machine — because an AI can only iterate where it
can verify. That pipeline is what this stack is built for.

## The loop is the machine

Every stage below is the same shape: propose, project, compare,
correct. The accuracy of the result comes from the loop, not from
any single estimate — an initial guess only decides how many
iterations it takes, and an iteration here is milliseconds of CPU
math. What makes the loop possible is that in Goeteia everything
is data all the way down: the mesh is bytes you can read, the
skeleton is a tree you can walk, the shader is a list you can
rewrite, and the rendered frame comes back out as bytes too. No
eyes required until the very end.

## Skeleton from video

Give it a turntable or a few views. Silhouette alignment recovers
the camera: rasterize the mesh's outline on the CPU, compare
against the reference mask, search — no gradients, no GPU.
Then 2D joint keypoints (any off-the-shelf pose model) initialize
the skeleton, and a reprojection loop refines it: hypothesize
joints, project them into the view, measure the pixel residual,
adjust. Left/right symmetry and constant bone length are not
assumptions to hope for — they are regularizers that collapse the
search space. Depth ambiguity dies under multiple frames: one
skeleton has to explain all of them at once.

## Texture from reference

Projection baking sprays the reference views onto the mesh and
down into UV space — the correspondence between a pixel in a view
and a texel in the atlas is one perspective projection, pure
arithmetic. Then the loop again: render, compare against the
reference, and translate "the left cheek is too dark" through that
same projection into exactly which texels to change. A texture
lint stands guard underneath — UV coverage, dead islands, seam
color mismatch, whole-image misalignment — so generated garbage is
rejected by a program before any human looks at it.

## Skinning under feedback

Skin weights are bytes in memory that can change between one frame
and the next — no re-export, no reimport, no engine restart. Pose
the character at a reference frame, compare the deformed
silhouette, nudge the weights, watch the result in the same
second. And behind the eye there are validators: bone lengths must
not stretch, symmetry must hold, no vertex's normal may collapse.
Wrong skinning is caught by an assertion, not by QA three weeks
later.

## Motion capture without the stage

One video of a martial artist, instead of an actor in a marker
suit. With the skeleton pinned, per-frame solving is the easy
direction — bone lengths are locked, only rotations remain. Frames
chain into clips; temporal smoothing eats the jitter; validators
check what matters (feet on the ground, bones constant, amplitude
in range). The source library stops being "actors we can hire" and
becomes "every video ever shot."

And the output is not frozen capture data. A clip here is
editable text: compress the strike from six frames to three,
exaggerate the windup, then *measure* that the timing changed the
way the director asked. Optical capture delivers data you clean;
this delivers material you keep working.

## Why this stack, specifically

The loop has hard prerequisites, and they are exactly what shipped
here: a complete glTF 2.0 skeletal pipeline that verifies headless
— joint matrices, vertex streams, animation samplers all
assertable from a terminal; drawing that refuses layout mismatches
instead of rendering garbage; inverse trigonometry and constant-
rate quaternion slerp for the solvers; and pixel readback, so the
machine can see the frame it just rendered. Second-scale
compilation and a runtime-writable asset memory close the
iteration to something an agent can drive thousands of times a
day. The API detail lives in the manual; the point of this page is
what the pieces add up to.

## Built for a fleet, not a seat

The traditional 3D stack is physically hostile to concurrent AI
work: one editor instance, a gigabyte install, binary assets that
git cannot merge. Ten agents on one project means nine waiting.
Here the entire product is text — scenes, shaders, meshes,
animation logic — so ten agents mean ten git worktrees, each with
its own second-scale compiles and headless assertions, on one
laptop, converging by ordinary merge. Reviews run as programs;
mutation tests tell you whether an assertion can actually fail;
nothing in the loop needs a window. Throughput in the AI era is
bounded by how parallel your environment lets the agents be —
this one was shaped for it.

## Light enough to be everywhere

The compiler is a 431KB wasm file that runs in the page, so the
workbench is a browser tab — a Chromebook or a tablet is enough
to model, skin, and iterate. Shipped artifacts are hundreds of
kilobytes, not a thirty-megabyte engine runtime, which is the
difference between "works in a product page on a phone" and
"works after a loading bar." And because generating, compiling
and running all happen in one conversation-sized surface, an AI
can hand you a disposable interactive 3D demo the way it hands
you a paragraph — made to answer one question, then thrown away.

## Where it stands

This is not a roadmap slide. The camera-from-silhouette solver,
the projection baker and the texture lint exist and hold
themselves to round-trip fixtures — synthetic views baked back to
the atlas and compared, recovered cameras checked against ground
truth, every claim a computable assertion. The per-frame pose
solver is in progress; lighting-from-reference and the feedback
protocol for vision models come next. The discipline does not
change as the pipeline grows: nothing ships on the strength of
looking right — it ships when a program agrees.
