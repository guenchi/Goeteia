# Skeletal 3D, verified headless

Goeteia's graphics stack now carries a complete skeletal animation
pipeline: glTF 2.0 characters in, skinned and animated on screen,
every step of it checkable from a terminal with no browser and no
GPU. This page is the tour of what landed and why it is shaped the
way it is.

## Full glTF 2.0 characters

`(web gltf)` loads what real assets actually contain, not just the
happy path:

- **Skinned meshes** — four bones per vertex, inverse bind
  matrices, joint palettes composed in SIMD into a resident staging
  arena. What draws is one uniform upload per skin, not a matrix
  tree walked per frame.
- **Animation clips** — LINEAR, STEP and CUBICSPLINE samplers,
  rotation, translation, scale and morph-weight channels, clips
  that pose completely (switching clips can never leave a stale
  bone behind), crossfades between any two clips, and an animation
  state machine — named states, per-transition fades, interrupts —
  packaged as `anim-machine`.
- **Morph targets** — position deltas blended per frame, including
  quantized ones.
- **Quantized and extended attributes** — byte and short
  positions, normals, UVs, u8/u16 joints and weights at their real
  strides; tangent frames and vertex colors carried through the
  canonical interleave.
- **Clip metadata** — `gltf-animation-duration` reads the clip
  length the parser computed, which is exactly what one-shot
  playback ("attack once, then back to idle") needs.

Deviations from the glTF ideal exist and are documented in the
library header where they live — nlerp between rotation keys, one
transition in flight at a time — rather than discovered in
production.

## Write the shader once, skin it for free

`gltf-skin-shader` is a combinator: it takes any static vertex
shader written in the s-expression GLSL dialect and returns its
skinned variant — joints and weights injected, every position and
normal reference rewritten through the palette, the varying
interface preserved so the original fragment shader still pairs.

Because shaders are data, this is a mechanical AST transform, not
string splicing. It also refuses to guess: attribute widths that
disagree with the loader's interleave, name collisions with
injected uniforms, references it cannot rewrite — each is a
compile-time error with a message, not a silently wrong render.
The built-in skinned shader is itself derived by this combinator
from the static one, so the two can never drift apart.

## Drawing that refuses to render garbage

`gltf-draw!` checks the program against the primitive before the
first byte uploads: attribute names *and* component widths, per
attribute, against the mesh's actual layout. A vec2 position
smuggled into a stride-compatible program, an instanced `i_*`
attribute that would silently read zeros — refused with an error
naming both sides. The alternative, familiar from every GL
codebase, is a mesh that collapses into triangle soup with nothing
in the console.

## Headless, down to the byte

Everything above verifies without a browser:

- `gltf-parse` runs on raw GLB bytes in Node — joint matrices,
  vertex streams, animation samplers all readable and assertable.
- A recording mock GL captures the exact command stream, so tests
  assert "the palette in force at this draw call was the bind
  pose" — not "it probably drew".
- The suite runs every test three ways — Chez-hosted compiler,
  the self-hosted compiler compiling itself, and the plain-JS
  backend — and byte-compares the first two.

This is what makes the stack usable by more than humans: an agent
that generates or edits an asset can compile, load, pose and
measure it in seconds, in CI, with numeric pass/fail — no eyeballs
required until the very end.

## Inverse trigonometry and slerp

`(web mat)` gains `flasin`, `flacos`, `flatan`, `flatan2` — pure
Scheme series, same construction as the existing `flsin`, measured
within a few ulps of a host `Math` and guaranteed to 1e-7. Inputs a
rounding error outside [-1, 1] clamp instead of poisoning the frame
with NaN. On top of them, `q-slerp` interpolates unit quaternions
at constant angular rate along the shortest arc.

Small functions, large unlock: IK, look-at, aim constraints and
camera solvers are all inverse-trig underneath, and none of them
were writable before.

## Pixels back out

`cmd-read-pixels!` and `fx-read-target!` close the last gap between
"numerically correct" and "actually on screen": the framebuffer
comes back into staging memory the instant the frame's single
bridge call returns — zero-copy, the upload contract pointed the
other way. Golden-image tests, color picking, and
machine-checkable rendering follow directly. The cost model (a
readback drains the pipeline) is documented, not hidden.

## Proven on hostile input

The pipeline was hardened against real legacy game assets — a
29-bone skeletal character with eleven animation clips, converted
from a 1990s engine format whose conventions (coordinate handed-
ness, quaternion conjugation, key ordering) had to be *inferred and
verified geometrically* rather than trusted. The converter checks
its own output: head above feet, left/right symmetry, constant bone
lengths. That discipline — every claim about an asset backed by a
computable check — is now the house style of the whole stack, and
`docs/limits.md` in the repository records every sharp edge found
along the way, with symptoms first.
